# Krutho credential SDK 2.0.2

## Summary
2.0.2 has no behavior change from 2.0.1. The source comments are rewritten for public distribution. It is the first release on the public package, `https://github.com/Krutho-com/krutho-sdk-swift`, which serves iOS and macOS from one package. Existing pins on the private releases route, `https://github.com/Krutho-com/krutho-releases`, keep working. The API, the native core and the platforms are the same as in 2.0.1.

## Platforms
| Platform | In this release | Minimum OS | Artifact |
|---|---|---|---|
| iOS | yes | iOS 13 (Apple silicon simulator: iOS 14) | `CredentialSdkCore.xcframework` in the Swift package `CredentialSdk` |
| macOS | yes | macOS 13 | the same XCFramework and package |
| Android | not in this release | | |

Build your app with Xcode 26 or later.

## Security-relevant changes
No change from 2.0.1. The security properties listed in the 2.0.1 notes, among them Secure Enclave only keys, a biometric scope bound to each transaction, single-use approvals and refused redirects, apply unchanged.

## Breaking changes and migration
None from 2.0.1. To move from the private releases route to the public package, change the package URL to `https://github.com/Krutho-com/krutho-sdk-swift`, the exact version to `2.0.2`, and the package name in the product reference to `krutho-sdk-swift`. Existing pins on `krutho-releases` need no change. Migration from 1.x is in the customer README.

## Minimum server version
2.0.2 has the same SDK behavior as 2.0.1 and needs the same server. Krutho runs that service for you, and you change nothing on the server side.

## Changes
- No behavior change from 2.0.1.
- Source comments rewritten for public distribution.
- First release on the public package `krutho-sdk-swift`, one package for iOS and macOS.
- `CredentialSdk.sdkVersion` returns `"2.0.2"`.

`CHANGELOG.md` lists every change.

## Verify
Follow `VERIFY.md` in the public package repository, with the root key fingerprint Krutho sends you out of band. `scripts/verify-public.sh` runs the steps: it checks the signature over `SHA256SUMS`, then the checksum of the compiled core and of every source file.

## Known limits
- Storage written by 1.x is proven to carry over on iOS simulator snapshots only, not on physical devices. Test an upgrade on your own devices before you ship.
- Android is not in this release.
- A device without a Secure Enclave, such as an Intel Mac without a T2 chip, cannot enroll.
- The software bill of materials covers the native core's Rust dependencies.
- Krutho's release process signs the provenance record and the bill of materials. The signature shows that process produced them; it is not an independent proof of the build.
